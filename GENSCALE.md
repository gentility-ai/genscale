# genscale

genscale is Gentility's fork of `tailscale.com`. The 6net connector pins it
with a `replace` in `gentility/node/go.mod`; nothing else consumes it.

The fork exists so 6net can run on a machine that also runs Tailscale. Every
divergence from upstream is listed below, and the patch stays that small.

## Tags

- A fork tag is the upstream tag it was cut from plus `.6net.N`:
  `v1.101.0-pre.6net.1` is upstream `v1.101.0-pre` with this patch.
- The patch lives on branch `6net`. A new upstream base gets a new branch cut
  from that tag, with the patch re-applied and `N` restarting at 1.
- **A tag, once pushed, is never moved or re-pushed.** proxy.golang.org caches
  it forever. A fix is the next `N`.

## Divergences

Each changed line carries a `genscale:` comment.

6net's range (`net/tsaddr/tsaddr.go`). The /48 moves; the reserved /64
indices stay as upstream carves them:

- `TailscaleULARange`: `fd06:6e7::/48` (upstream `fd7a:115c:a1e0::/48`).
- `TailscaleServiceIPv6String`: `fd06:6e7::53`.
- `TailscaleViaRange`: `fd06:6e7:0:b1a::/64`.
- `Tailscale4To6Range`: `fd06:6e7:0:ab12:4843:cd96:6200::/104`.
- `TailscaleEphemeral6Range`: `fd06:6e7:0:efe3::/64`.

Linux policy routing, so we sit beside an installed `tailscaled`:

- `wgengine/router/osrouter/router_linux.go`: route table 66 (upstream 52);
  rule priority base 5100, rules 5110-5170 (upstream 5200); on OpenWRT with
  mwan3, base 1400 (upstream 1300).
- `net/netmon/netmon_linux.go`: `tsTable` 66, to match.
- `util/linuxfw/linuxfw.go`: the IPv6 policy-routing probe rule looks up
  table 66 (upstream 52).

Linux netfilter, so stopping or cleaning up never removes an installed
`tailscaled`'s rules (ours and theirs share names and match arguments):

- `wgengine/router/osrouter/router_linux.go` `Close`: deletes the connmark
  save/restore rules only when `connmarkEnabled`, i.e. this router added them
  (upstream deletes them unconditionally).
- `wgengine/router/osrouter/router_linux.go` `cleanUp` (the
  `router.CleanUp` hook): a no-op (upstream runs `IPTablesCleanUp` and
  `NfTablesCleanUp`, which delete the `ts-*` chains and their hooks by name).
  6net runs with netfilter off and never adds them.

Resolver files, so we never touch Tailscale's:

- `net/dns/manager_darwin.go`: `/etc/resolver` header
  `# Added by gentility (6net)` (upstream `# Added by tailscaled`), and the
  search file `search.6net` (upstream `search.tailscale`). Cleanup deletes
  only files carrying our header.
- `net/dns/resolvconffile/resolvconffile.go`: the resolv.conf marker reads
  `generated by gentility (6net)`, and the line pointing at Tailscale's
  `resolvconf-overwrite` docs is dropped.
- `net/dns/openresolv.go`: the openresolv snippet is `gentility` (upstream
  `tailscale`), so `SetDNS` and `CleanUp` never replace or delete
  Tailscale's.
- `net/dns/debian_resolvconf.go`, `net/dns/resolvconf-workaround.sh`: the
  Debian resolvconf record is `tun-gentility.inet` (upstream
  `tun-tailscale.inet`) and the libc hook is `update-libc.d/gentility`
  (upstream `update-libc.d/tailscale`).
- `net/dns/direct.go`: recognises only our marker; no longer removes
  upstream's legacy `/etc/resolv.tailscale.conf` on close.
- `net/dns/resolvconfpath_default.go`, `net/dns/resolvconfpath_gokrazy.go`:
  backup `resolv.pre-gentility-backup.conf` (upstream
  `resolv.pre-tailscale-backup.conf`).

MagicDNS on macOS, where the OS configurator is the `/etc/resolver`
`darwinConfigurator` (not Tailscale.app's NetworkExtension):

- `net/dns/manager.go` `compileConfig`: on darwin, when the base config
  parses, `MatchDomains` is every route domain (upstream sets them only on
  iOS, and the configurator writes a resolver file per MatchDomain and
  nothing else, so no query reached quad-100). `Routes["."]` keeps the base
  nameservers, as upstream.
- `ipn/ipnlocal/local.go` `magicDNSRootDomains`: the reverse zone is 6net's,
  `0.0.0.0.7.e.6.0.6.0.d.f.ip6.arpa.`, and the `64-127.100.in-addr.arpa.`
  zones are dropped (upstream routes Tailscale's ULA and CGNAT zones, which
  would capture an installed Tailscale's PTR lookups and, under `tailscaled`
  on macOS, overwrite its resolver files).
- `net/dns/manager_darwin.go` `SetDNS`: every resolver file carries
  `flags a aaaa`. On a Mac with no routable IPv6, configd marks a resolver
  file A-only and mDNSResponder suppresses getaddrinfo's AAAA questions, so
  6net's IPv6-only names never resolved for applications. The `flags`
  keyword is parsed by configd's `dnsinfo_flatfile.c`; resolver(5) does not
  document it.

Host-interface detection, so a co-installed Tailscale.app is never taken
for a usable interface:

- `net/netmon/state.go`: `hasTailscaleIP` also matches upstream's
  `fd7a:115c:a1e0::/48`, so a macOS utun carrying it counts as a Tailscale
  interface even on a v6-only tailnet. `tsaddr.IsTailscaleIP` stays ours
  alone. Pinned by `net/netmon/state_genscale_test.go`.

Refused reach, so a refused connection can be seen and reported:

- `net/tstun/wrap.go` `filterPacketInboundFromWireGuard`: the TSMP
  "rejected" notice for a TCP SYN the filter drops is sent for IPv6 as well
  as IPv4 (upstream IPv4 only). 6net is IPv6-only, so upstream's sender
  never heard it was refused. Pinned by `net/tstun/wrap_genscale_test.go`.
- `wgengine/userspace.go`: `Config.OnNoPeer(src, dst, pkt)`, called for
  each outbound packet no peer owns, just before wireguard-go drops it
  (upstream drops silently). `SetPeerByIPPacketFunc`'s closure is now the
  method `peerForPacket`, so the hook is testable. Pinned by
  `wgengine/userspace_genscale_test.go`.

Endpoints on a LAN, so two 6net nodes beside each other take the IPv6 path
(the Desk phone's design, docs/plans/2026-10-27-desk-mobile-fast-open-design.md
A4–A5 in the gentility repo):

- `net/netmon/state.go` `isProblematicInterface`: on darwin, `bridge100` and
  above and `vmenet*` are problematic (Virtualization.framework host-only
  networks, reachable only from the Mac's own VMs; a far peer pinged them,
  and the Mac's own path choice tied them with the LAN). `bridge0` stays.
  Internet Sharing's `bridge100` is excluded with them (the other side's
  disco ping still teaches the Mac its address), and iOS is left alone
  because its `bridge100` is the Personal Hotspot. The rule is
  `problematicInterfaceName(goos, name)`, pinned by
  `net/netmon/state_genscale_test.go`.
- `net/netmon/state.go` `LocalAddresses`: unique local addresses (fc00::/7)
  are regular addresses, capped at two per subnet like global IPv6 (upstream
  offers them only when a host has nothing else, for Cloud Run). 6net's own
  range and Tailscale's `fd7a:115c:a1e0::/48` are skipped: a tunnel's address
  is not a LAN's. The 169.254 fallback is unchanged. Pinned by
  `net/netmon/state_genscale_test.go`.
- `wgengine/magicsock/magicsock.go` `determineEndpoints`: a local IPv6
  address is offered on the IPv6 socket's port, and not at all when that
  socket is unbound (upstream gives every local address the IPv4 socket's
  port; with no configured port the two sockets differ, and the IPv6
  endpoint named a port nothing listened on). `betterAddr`'s +10 for IPv6 is
  upstream's and stays. Pinned by `wgengine/magicsock/magicsock_genscale_test.go`.

Tests in `net/tsaddr`, `net/dns/...`, `net/netmon`,
`wgengine/router/osrouter` and `ipn/ipnlocal`'s `TestDNSConfigForNetmap` are
updated to these values; `net/tsaddr` pins the
ranges and refuses an address in Tailscale's ULA.

## Deliberately not changed

- **IPv4 CGNAT (`100.64.0.0/10`) and `100.100.100.100`.** 6net is IPv6-only;
  a node with no IPv4 address gets `OnlyIPv6`, so the v4 service address is
  never installed.
- **The bypass fwmark `0x80000`.** Both daemons use it to mean "skip the VPN
  tables, use main"; sharing it changes no behaviour.
- **`net/tstun/tun.go`'s plan9 literal.** Plan 9 is not a 6net platform.
- **`cmd/natc`'s `fd7a:115c:a1e0:a99c::/64`.** The NAT connector is an
  upstream binary the connector never links or builds.
- **Comments in `tailcfg`, `types/netmap` and `wgengine/netstack`** that cite
  Tailscale's range as an example.
- **Upstream tests outside the packages above** still assert
  `fd7a:115c:a1e0`. They are not run for genscale.
